# Deploying MiniFlow

MiniFlow ships as three pieces: a **Neon** Postgres database, the **API** on
**Render**, and the **web** app on **Vercel**. All three have free tiers.

Each step below is something you do in a browser with your own accounts —
follow them in order.

---

## 0. Push the code to GitHub

Render and Vercel both deploy from a GitHub repo.

```bash
# create an empty repo on github.com first, then:
git remote add origin https://github.com/<you>/miniflow.git
git push -u origin main
```

---

## 1. Database — Neon

1. Sign up at <https://neon.tech> and create a project (Postgres 16).
2. From the dashboard, copy the **connection string**. It looks like:
   `postgresql://user:password@ep-xxx.region.aws.neon.tech/dbname?sslmode=require`
3. Keep it handy — it becomes `DATABASE_URL` in step 2.

> The API rewrites a bare `postgresql://` URL to use the `psycopg` driver
> automatically, so paste Neon's string verbatim.

---

## 2. API — Render

The repo includes [`render.yaml`](../render.yaml), a Render blueprint.

1. Sign up at <https://render.com> and connect your GitHub account.
2. **New + → Blueprint**, select the repo. Render reads `render.yaml` and
   provisions the `miniflow-api` web service.
3. When prompted, set the **non-synced** environment variables:
   - `DATABASE_URL` — the Neon connection string from step 1.
   - `LLM_API_KEY` — your OpenRouter API key (<https://openrouter.ai/keys>).
   - `BACKEND_CORS_ORIGINS` — leave blank for now; fill it in step 4.
   - `SECRET_KEY` is generated automatically.
4. Deploy. The start command runs `alembic upgrade head` first, so the schema
   is created on the first boot.
5. When it is live, note the URL (e.g. `https://miniflow-api.onrender.com`)
   and check `https://<that-url>/health` returns `{"status":"ok"}`.

> Render's free tier sleeps after inactivity; the first request after a while
> takes ~30s to wake.

---

## 3. Web — Vercel

1. Sign up at <https://vercel.com> and import the GitHub repo.
2. Set **Root Directory** to `web` — Vercel auto-detects Next.js.
3. Add an environment variable:
   - `NEXT_PUBLIC_API_URL` — the Render API URL from step 2.
4. Deploy. Note the resulting URL (e.g. `https://miniflow.vercel.app`).

---

## 4. Wire CORS and verify

1. Back in Render, set `BACKEND_CORS_ORIGINS` to the Vercel URL from step 3
   (no trailing slash) and let the API redeploy.
2. Open the Vercel URL and run the full flow end to end:
   sign up → create a project → add a member → create and move tasks →
   try the AI features (generate subtasks, summarize a project, draft tasks).
3. Update the **Live demo** line at the top of [`README.md`](../README.md)
   with the Vercel URL.

---

## Environment variable summary

| Where  | Variable               | Value                                  |
| ------ | ---------------------- | -------------------------------------- |
| Render | `DATABASE_URL`         | Neon connection string                 |
| Render | `SECRET_KEY`           | auto-generated by the blueprint        |
| Render | `LLM_API_KEY`          | OpenRouter API key                     |
| Render | `BACKEND_CORS_ORIGINS` | the Vercel web URL                     |
| Vercel | `NEXT_PUBLIC_API_URL`  | the Render API URL                     |
